ALL THREE PORTALS MUST BE FULLY SYNCED IN REAL TIME.

When ANYTHING changes anywhere:
- Admin approves a store → Store owner sees "Approved" status instantly
- Store owner updates store hours → Customer website reflects it immediately
- Store owner adds a product → Admin sees it in pending queue instantly
- Admin toggles store active/inactive → Customer website shows/hides store instantly
- Store owner changes product price → Customer website updates price in real time
- Admin suspends a store → Store portal shows suspended status + customer website hides store
- Store owner changes opening hours → Store active/closed status auto-updates on customer website
- New order placed → Store portal shows notification + sound instantly
- Admin bans a user → User is kicked from all sessions instantly
- New chat message sent → Recipient sees it instantly across any portal

Use Socket.IO to broadcast ALL these events across /customer, /store, /admin namespaces.
Every database mutation must emit a socket event.
Every frontend must listen and update UI without page refresh.

This is a first-class feature built from scratch.
Database tables, Socket.IO events, API routes, and shared UI components.

13A — Database Schema

  -- Conversations table
  conversations (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    type                TEXT NOT NULL,
      -- 'admin_store'    : Admin ↔ Store Owner
      -- 'admin_customer' : Admin ↔ Customer
      -- 'store_customer' : Store Owner ↔ Customer (only if customer interacted)
    adminId             UUID REFERENCES users(id) ON DELETE SET NULL,
    storeId             UUID REFERENCES stores(id) ON DELETE CASCADE,
    customerId          UUID REFERENCES users(id) ON DELETE SET NULL,
    storeOwnerId        UUID REFERENCES users(id) ON DELETE SET NULL,
    lastMessageAt       TIMESTAMPTZ DEFAULT now(),
    lastMessageText     TEXT,
    isArchivedAdmin     BOOLEAN DEFAULT false,
    isArchivedStore     BOOLEAN DEFAULT false,
    isArchivedCustomer  BOOLEAN DEFAULT false,
    createdAt           TIMESTAMPTZ DEFAULT now()
  )

  -- Messages table
  messages (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    conversationId  UUID REFERENCES conversations(id) ON DELETE CASCADE,
    senderId        UUID REFERENCES users(id) ON DELETE SET NULL,
    senderRole      TEXT NOT NULL,
      -- 'admin' | 'store_owner' | 'customer'
    content         TEXT,
    messageType     TEXT DEFAULT 'text',
      -- 'text' | 'image' | 'file' | 'order_card' | 'product_card' | 'system'
    attachmentUrl   TEXT,
    attachmentName  TEXT,
    metadata        JSONB,
      -- order_card:   { orderId, orderTotal, itemCount, status }
      -- product_card: { productId, productName, price, image }
    isRead          BOOLEAN DEFAULT false,
    readAt          TIMESTAMPTZ,
    createdAt       TIMESTAMPTZ DEFAULT now()
  )

  -- Message read receipts
  message_reads (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    messageId   UUID REFERENCES messages(id) ON DELETE CASCADE,
    userId      UUID REFERENCES users(id) ON DELETE CASCADE,
    readAt      TIMESTAMPTZ DEFAULT now(),
    UNIQUE(messageId, userId)
  )

  CREATE INDEX ON messages(conversationId, createdAt);
  CREATE INDEX ON conversations(storeId, lastMessageAt);
  CREATE INDEX ON conversations(customerId, lastMessageAt);
  CREATE INDEX ON conversations(adminId, lastMessageAt);

13B — Who Can Chat With Whom

  Admin       ↔  Any Store Owner    (type: 'admin_store')
  Admin       ↔  Any Customer       (type: 'admin_customer')
  Store Owner ↔  Admin              (same as above, store owner can initiate)
  Store Owner ↔  Any customer who has:
                 - Placed an order at this store, OR
                 - Added any product from this store to their cart
                 (type: 'store_customer')
  Customer    ↔  Store Owner of a store they ordered from or carted from
  Customer    ↔  Admin (as support contact)

  Store owner CANNOT initiate chat with a customer who has never interacted
  with their store. This protects customer privacy.

13F — Socket.IO Events for Chat

  Each conversation has a Socket.IO room: conversation:${conversationId}
  When user opens chat, they join all their conversation rooms.
  Sending a message emits to the room → all participants receive it instantly.

  Events:
  'new_chat_message'      { conversationId, messageId, senderId, senderRole,
                            content, messageType, metadata, createdAt }
  'message_read'          { conversationId, messageId, readerId, readAt }
  'conversation_started'  { conversationId, type, participants }
  'user_online'           { userId }
  'user_offline'          { userId }

13G — Chat Message Types

  text        Plain text. Render as bubble.

  image       Upload to storage on send, store URL in attachmentUrl.
              Render as thumbnail, click to expand full size.

  file        Upload to storage, store URL + filename.
              Render as pill: filename + size + download icon.

  order_card  Sent automatically when a new order is placed.
              System auto-creates/opens store_customer conversation and sends
              this message type with metadata: { orderId, total, itemCount, status }
              Renders as compact order summary card.

  product_card Store owner can share a product in chat.
              "Share Product" button lets store owner pick one of their products.
              Renders as compact card: image + name + price.
              Customer can click it to open <ProductDetailModal>.

  system      Auto-generated event messages, centered in gray.
              e.g. "Order #ABC123 status changed to Ready"
